# План проверок авторизации SauceDemo

## Application Overview

Объект проверки: форма входа и доступ к защищённой странице https://www.saucedemo.com/inventory.html. Стартовая точка: tests/seed.spec.ts. План основан на исследовании стенда, а не на формальных требованиях: наблюдаемое поведение не считается автоматически правильным. Каждый сценарий выполняется независимо в новом браузерном контексте без сохранённых cookies, storage и авторизованной сессии, если иное не указано в предусловиях. Пароль для опубликованных учётных записей: secret_sauce. Точные формулировки ошибок, правила нормализации ввода и политика сессии требуют уточнения и не должны фиксироваться как эталон только по текущему поведению. Сортировка, каталог, корзина и оформление заказа после входа вне области плана.

## Test Scenarios

### 1. Позитивные сценарии

**Seed:** `tests/seed.spec.ts`

#### 1.1. AUTH-001. Успешный вход standard_user по кнопке Login

**File:** `tests/auth.spec.ts`

**Steps:**

1. Предусловия: новая браузерная сессия; открыта https://www.saucedemo.com/; пользователь не авторизован; поля Username и Password пусты.
2. Тестовые данные: Username = standard_user; Password = secret_sauce.
3. Ввести standard_user в поле Username и secret_sauce в поле Password.
   - expect: Введённые значения приняты формой; пароль визуально маскируется.

4. Нажать кнопку Login.
   - expect: Выполнен переход на https://www.saucedemo.com/inventory.html.
   - expect: Отображается заголовок Products и содержимое каталога.
   - expect: Форма входа закрыта; авторизованная сессия создана; сообщение об ошибке авторизации отсутствует.

#### 1.2. AUTH-002. Успешный вход всех опубликованных незаблокированных пользователей

**File:** `tests/auth.spec.ts`

**Steps:**

1. Предусловия: для каждой строки тестовых данных использовать новую браузерную сессию и открыть https://www.saucedemo.com/; пользователь не авторизован.
2. Тестовые данные: Username по очереди standard_user, problem_user, performance_glitch_user, error_user, visual_user; Password = secret_sauce для каждой строки. locked_out_user проверяется отдельным негативным сценарием.
3. Для каждой строки независимо ввести учётные данные и нажать Login.
   - expect: Для каждой опубликованной незаблокированной учётной записи выполнен переход на /inventory.html.
   - expect: Для каждой учётной записи доступны заголовок Products и защищённое содержимое.
   - expect: Особенности отображения или работы каталога для специальных пользователей не влияют на результат именно проверки авторизации.

**File:** `tests/auth.spec.ts`

**Steps:**

1. Предусловия: новая браузерная сессия без cookies и storage авторизованного пользователя; страница входа ещё не использовалась.

   - expect: Если требования предписывают завершать сессию при обновлении, ожидание должно быть изменено на безопасный возврат к форме входа без отображения защищённых данных.
